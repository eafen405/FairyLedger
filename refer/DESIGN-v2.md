# 柴油机配件进销存系统 —— 设计方案 v2

> 版本：2026-08-09 v2（根据主人反馈修订：读图不可靠 + 价格随客户/时间变化）

## 0. 需求分析

业务：柴油机配件（缸盖、喷油泵、垫片、调整臂等），手写账本记录。

核心诉求（主人原话归纳）：
1. 有进货、有售出，统一记录
2. 能查找**特定产品**的全部相关记录
3. 同一产品在**不同时间、对不同客户**可以有**不同单价**（真实业务：老客户价、涨价、专享价）
4. 数据要准确——手写体读图不可靠，不能把图片转录当数据源

## 1. 技术选型

- **SQLite 单文件库**（零依赖、单文件备份、支持任意时点查询）
- Python 标准库 `sqlite3` + 命令行脚本（CLI）
- 无 Web/无 GUI：主人通过飞书对话让 Fairy 代录，或本地跑脚本

## 2. 数据模型（核心设计）

### 2.1 表结构

```
products                   商品表
  id            PK
  name          名称（缸盖总成）
  model         型号（210 / 300R.14.14）—— 允许空
  unit          单位（件/个/套）
  category      分类（可空：发动机件/制动件/滤清件…）
  min_stock     库存预警线（可空）
  note          备注
  created_at    建档时间
  UNIQUE(name, model)

counterparties              往来单位表
  id            PK
  ctype         类型：customer=客户 / supplier=供应商
  name          名称（徐丽 / 济南配件商）
  region        地区（湖南/河南/烟台）
  phone         电话
  note          备注
  created_at

transactions                流水表（唯一事实来源）
  id            PK
  biz_date      业务日期 YYYY-MM-DD
  biz_type      类型：purchase=进货 / sale=售出 / purchase_return=进货退货 / sale_return=售出退货
  product_id    FK → products
  qty           数量（正数；退货用类型区分，不用负数）
  price         实际成交单价（每笔独立！）
  amount        金额 = qty × price（自动算，可覆盖）
  counterparty_id FK → counterparties（售出=客户，进货=供应商，可空）
  cost          成本快照（进货时=进价；售出时=当时加权平均成本）
  note          备注
  created_at
  索引：biz_date, product_id, counterparty_id

customer_prices             客户专享价表（辅助录入，不是事实）
  id            PK
  product_id    FK → products
  counterparty_id FK → counterparties（必须 customer）
  price         该客户对该商品的常购价
  valid_from    生效日期
  note          备注
  UNIQUE(product_id, counterparty_id)
```

### 2.2 价格机制（回应"不同时间不同客户不同单价"）

原则：**成交价记在流水里，每一笔独立**——这就是完整的价格历史。

- 查"某产品价格变化"→ 按时间排它的所有售出记录，单价自然呈现涨价/降价轨迹
- 查"某客户买某商品多少钱"→ 按客户+产品过滤流水
- `customer_prices` 只是**录入辅助**：录同一客户买同一商品时自动带出上次成交价/专享价，可改可确认，避免每次手输

### 2.3 成本与毛利（移动加权平均）

- `products` 不存静态进价；每次进货时重算该商品的**移动加权平均成本**
  `new_avg = (旧库存×旧均成本 + 本次进货量×进价) / (旧库存 + 本次进货量)`
- 每笔**售出**时，把当时的加权平均成本**快照**到该行的 `cost` 字段
- 毛利 = Σ(售出金额 − 售出数量×cost)，**历史毛利不受后续进货影响**，永远可回溯
- 负库存（先卖后进）时暂用最近一次进价，进货补录后自动校正

### 2.4 库存

- 实时计算：`库存 = Σ(进货+进货退货调整) − Σ(售出)`
- `min_stock` 低于预警线时提示补货
- 支持按任意日期算历史库存（用于盘点对账）

## 3. 功能清单

### 录入
- `sell` 记售出：日期/商品/数量/成交价/客户/备注
- `buy` 记进货：日期/商品/数量/进价/供应商/备注
- 自动带出：同客户同商品的历史价/专享价（可改）
- 支持退货：`sell --return` / `buy --return`
- 商品、客户自动建档复用；多型号同名（打孔座 300.13.14A / 300.18.12）用精确 name+model 区分

### 查询
- `product-history`：某产品全部进售记录（时间线、单价变化、库存轨迹）
- `customer-history`：某客户全部交易（含欠款视角）
- `stock`：当前库存 + 预警
- `stock --date`：任意日期库存快照
- `daily` / `monthly`：日报月报
- `profit`：毛利（按时间/产品/客户分组）
- `price-history`：某产品价格变化一览
- `top`：热销排行（按数量/金额）

### 导出与维护
- `export`：全库导出 Excel（流水/商品/客户/库存/毛利多 Sheet）
- `backup`：单文件备份
- 数据修正：记录错误时走"冲销"（记一笔相反类型）而不是物理删除，保留审计轨迹

## 4. 数据准确性方案（回应"读图不准确"）

1. **图片只作辅助转录**，标注 `[需核对]`，主人确认后才入库
2. 优先主人**口述/文字**录入（发飞书消息），Fairy 负责敲命令
3. 金额一律自动算（qty×price），对账时与手写本合计比对
4. 定期对账：`daily` 输出当日合计，主人与账本核对

## 5. 需要主人拍板的 3 个问题

1. **成本算法**：移动加权平均（推荐，毛利最准）vs 最近一次进价（简单）vs 每次售出手动录成本（最准但费事）？
2. **要不要退货/冲销**：配件生意有没有退货情况？有则保留退货类型
3. **要不要应收应付（赊账）**：客户月结/欠款需要记录吗？需要则加一个 `payments` 表
